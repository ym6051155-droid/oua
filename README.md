# أهليّة — منصة جامعة أمدرمان الأهلية (PWA)

واجهة عربية RTL مبنية بـ Next.js + TypeScript + Tailwind CSS، مع Supabase للمصادقة وقاعدة البيانات وRLS. هذا **هيكل MVP قابل للتطوير** وليس نظاماً إنتاجياً مكتملاً؛ وحدات الواجبات والحضور ومنتدى الأسئلة وقنوات التنبيه الخارجية تحتاج استكمال واجهاتها وربط مزوديها قبل الاعتماد الأكاديمي.

## المتطلبات
- Node.js 20+
- مشروع Supabase

## التشغيل المحلي
1. انسخ `.env.example` إلى `.env.local` وضع `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`.
2. في Supabase SQL Editor نفّذ `supabase/schema.sql`.
3. أنشئ Storage bucket باسم `course-materials`. يوصى بجعله **خاصاً** وتوليد Signed URLs بعد إضافة سياسات التخزين.
4. ثبّت الحزم وشغّل المشروع:
   ```bash
   npm install
   npm run dev
   ```
5. افتح `http://localhost:3000`.

## ما يتضمنه الهيكل
- صفحات عربية متجاوبة: الرئيسية، تسجيل الدخول، التسجيل، لوحة التحكم، إعدادات الإشعارات، صفحة القروب.
- التسجيل كطالب أو طلب حساب أستاذ قيد الاعتماد.
- رقم واتساب مركّب من مفتاح الدولة والرقم المحلي.
- عرض القروبات المطابقة لتخصص الطالب وسمستره، وإنشاء القروبات للأستاذ المعتمد فقط.
- إعلانات مثبتة، مشاركة الإعلان عبر WhatsApp، رفع PDF وMP3، ومشغل صوتي.
- Manifest وService Worker بتخزين أساسي للشاشة الرئيسية والصفحات التي جرى طلبها.
- مخطط SQL للجداول والعلاقات وسياسات RLS الأساسية.

## نقاط يجب استكمالها قبل الإنتاج
1. **منع تصعيد الصلاحيات:** لا تعتمد على بيانات `user_metadata` أو كود الأستاذ المرسل من المتصفح. التسجيل الحالي يرسل الكود في بيانات التسجيل فقط لأغراض واجهة النموذج، لكن لا يفعّله الخادم؛ أضف API Route موثوقاً يتحقق من `PROFESSOR_INVITE_CODE` على الخادم أو اجعل الأدمن يفعّل الحساب. راجع سياسة إنشاء المستخدمين وسياسات تحديث الدور، واجعل تغيير `role` و`is_approved` ممكناً للأدمن عبر وظيفة آمنة فقط.
2. **إكمال الوحدات:** إنشاء التكليفات وتسليم الملفات وتقييمها، فتح جلسة الحضور لمدة 10 دقائق وإغلاقها تلقائياً عبر قاعدة البيانات/وظيفة مجدولة، تصدير CSV، ومنتدى Q&A مع تثبيت الإجابة الموثقة.
3. **الإشعارات:** Web Push يتطلب VAPID/OneSignal/FCM واشتراك Push فعلي؛ البريد يحتاج Resend أو SMTP؛ WhatsApp يتطلب مزوداً رسمياً وقوالب/موافقات مناسبة؛ Messenger يتطلب تطبيق Meta مع Webhook وPSID ومراجعات المنصة. المتغيرات في `.env.example` تهيئة فقط وليست تكاملاً فعلياً.
4. **PWA/offline:** أضف أيقونات PWA بأحجام 192 و512، اختبر استراتيجية الكاش، ولا تخزّن استجابات شخصية أو ملفات خاصة في Cache عام. ملفات المحاضرات الخاصة تحتاج Signed URLs وتخزيناً محسوباً.
5. **التسجيل:** فعّل تأكيد البريد وحدود المحاولات وسياسة كلمة مرور مناسبة، وطبّق تحقق رقم الهاتف بحسب الدولة، وسياسة خصوصية وموافقة واضحة قبل إرسال تنبيهات خارجية.
6. **التنفيذ الأمني:** راجع كل سياسات RLS، وسياسات Storage، وتدفقات الأدمن قبل نشر بيانات طلاب حقيقية. لا تضع مفاتيح Service Role في الواجهة الأمامية.
7. **اختبارات:** أضف اختبارات صلاحيات وتكامل، تحققاً من الملفات المرفوعة (الحجم/MIME)، حماية من السبام، سجلات تدقيق، نسخاً احتياطية ومراقبة.

## النشر
يمكن نشر واجهة Next.js على Vercel أو منصة Node.js، مع وضع المتغيرات السرية في إعدادات الخادم فقط. نفّذ `npm run build` قبل النشر.

## ملاحظة أمنية مهمة
واجهة التسجيل في هذا الـ MVP ليست كافية وحدها لحماية دور الأستاذ؛ يجب إضافة تحقق خادمي موثوق وتقييد سياسات تحديث الدور والموافقة قبل استخدامه مع طلاب حقيقيين. لا تعتبر أي قناة إشعار فعّالة ما لم تُربط وتُختبر بمفاتيح مزودها.
